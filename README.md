# PaperFlow

> 发散地读论文，收敛地积累理解。

PaperFlow 是**每周跑一次**的一个小脚本。

它读你上周写的笔记和你的长期目标，去外面检索论文、按引用量和年份过一遍，
再让 AI 挑出这一周该读的 12 篇，然后写一份阅读清单、一份周报，并把论文推进 Zotero。

你负责读和写笔记；它负责「别读偏、别重复、别断片」。

---

## 0. 它不做什么（先看这个）

| 不做 | 为什么 |
| --- | --- |
| **不碰 git** | 你要的是「这周该看什么」，不是一次 commit。整个脚本里没有一条 git 命令。 |
| **不替你写代码，也不复现论文** | 工程部分只出**建议**——一个任务、需要什么、完成标准、预估工时，写在周报第 7 节。代码你自己写。 |
| **不替你读** | 它只产出清单和判断。真正让推荐变准的，是你读完以后写下的笔记。 |
| **不装模型就不干活** | 模型不可用时 `week` 直接报错退出（退出码 1），**不写任何文件**。宁可下周重跑，也不给你一份「按分数排个序」的假推荐。 |

唯一例外是 `summary`：它主要在算数字，没模型也能出结果，只是叙述部分留空。

## 1. 三条命令

整个工具只有三条命令，没有隐藏功能、没有插件、没有配置文件语法要学。

| 命令 | 什么时候跑 | 干什么 |
| --- | --- | --- |
| `init` | 只有第一次 | 配置 Obsidian 库、第 1 周起始日、长期目标位置 |
| `week` | 每周一次 | 回顾上周 → 检索筛选 → **先落盘**（账本、阅读清单、周报）→ 最后推 Zotero |
| `summary` | 每月一次（想每周也行） | 出一份给人看的周/月总结 |

> 「先落盘」这条不是随手排的：Zotero 是本机服务，你没开它、或它卡住了都不该让这一周白跑。
> 所以账本和阅读清单一定先写完，Zotero 只作为最后一步，结果写进周报。

## 2. 安装

需要一个 Python（3.10 以上都行，开发环境用的是 3.12）。

```powershell
cd <这个目录>

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

运行时依赖只有一个：`requests`。其余全部是标准库。

### 配置 `.env`

把 `.env.example` 复制成 `.env`，至少填两项：

```ini
PAPERFLOW_VAULT=D:\Obsidian\MyVault   # 你的 Obsidian 库根目录
LLM_API_KEY=sk-...                    # 任何 OpenAI 兼容端点
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
```

填了 `PAPERFLOW_VAULT` 之后，`init` 就不用每次带 `--vault` 了。

## 3. 十分钟跑通

### 第一步：`init`

```powershell
.\.venv\Scripts\python.exe paperflow.py init --vault "D:\Obsidian\MyVault"
```

它会做四件事，**不覆盖任何已有文件**：

1. 在**库里**建 `周报月报\`，并建空的账本 `进度.csv`
2. 建本周的文件夹（`2026-09-21_09-27\`）
3. 在**库根**放一个 `本周.md` 模板（脚本每次都会读它）
4. 如果 `<vault>\长期目标\` 还不存在，建一个 `长期目标.md` 模板

参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--vault` | `PAPERFLOW_VAULT` | Obsidian 库根目录。两处都没有就报错（退出码 2） |
| `--goals` | `<vault>\长期目标` | 长期目标文件**或**文件夹。你自己维护，脚本只读、从不改写 |
| `--start` | 下一个周一 | 第 1 周的周一，`YYYY-MM-DD`。**定下来就别改**，否则「第 n 周」全部错位 |
| `--per-week` | `12` | 每周推荐几篇（12 = 5 篇精读 + 7 篇泛读） |
| `--force` | 关 | 重新生成 `config.json`。不会删你的笔记，也不会清空账本 |

### 第二步：写长期目标（唯一必须认真写的文件）

打开 `<vault>\长期目标\长期目标.md`，把模板换成你自己的话。

写好它的标准：**六个月后你希望自己能讲清什么、能做什么**。每条一行，越具体越好。比如

```text
能说清 metastability 和 criticality 的区别，并知道怎么从 EEG 里估计它们。
能自己搭一条「静息态 EEG → 状态序列 → 转移概率」的分析流程。
```

这个文件是 AI 每周判断「这次选得散不散」的主要依据。它含糊，推荐就含糊。

### 第三步：试跑一周

```powershell
.\.venv\Scripts\python.exe paperflow.py week --dry-run --no-zotero
```

`--dry-run` 不写文件、不动 Zotero，只把结果打出来。确认推荐靠谱了，去掉这两个开关正式跑：

```powershell
.\.venv\Scripts\python.exe paperflow.py week
```

## 4. `week` 到底做了什么

```mermaid
flowchart LR
    A[读长期目标 + 本周.md] --> B[读上次运行以来的新笔记]
    B --> C[推断检索式 / 或用 --topic]
    C --> D[多源检索]
    D --> E[合并去重 → 引用门槛 → 年份窗口]
    E --> F[AI 挑 12 篇 = 5 精读 + 7 泛读]
    F --> G[写账本 + 写阅读清单]
    G --> H[推 Zotero（可选，失败只记一行警告）]
    H --> I[写周报 → 记运行日期]
```

顺序是刻意的：**本地产出先写完，Zotero 排在最后。** 第 7 步之后才有第 8、9 步，
所以 Zotero 连不上时你已经拿到账本和阅读清单，周报里会写明为什么没推成功；
只有周报是等推送结果之后才写的，因为周报要把推送结果写进去。
`--dry-run` 在第一步之前就返回，一个字节都不写。

每一步都能在周报里看到它读了什么、筛掉了什么。AI 的判断和你自己的数据是分开写的，所以你能分辨哪句话是它说的。

### `week` 的参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--dry-run` | 关 | 试跑：不写文件、不动 Zotero |
| `--no-zotero` | 关 | 这一周不推 Zotero（其余照旧） |
| `--topic` | 自动推断 | **覆盖**自动推断的检索式，用 `\|` 分隔多条。想把方向钉死一段时间就用它 |
| `--per-week` | `init` 里设的 | 这一周推荐几篇 |
| `--deep` | 每周篇数的 2/5 | 最多几篇标为精读（12 篇 → 5 篇） |
| `--min-citations` | `50` | 引用门槛基数，见下一节。`0` = 关掉门槛（不推荐） |
| `--years` | `5` | 优先只收近 N 年的论文。`0` = 不限年份 |
| `--max-years` | `10` | 近 N 年凑不够候选时的放宽上限 |
| `--min-year` | 无 | 硬下限：只收这个年份之后的 |
| `--sources` | `auto` | 逗号分隔：`s2, openalex, arxiv, pubmed` |
| `--seed` | 无 | 种子论文 ID / DOI / 链接，可重复给 |
| `--full` | 关 | 忽略上次运行时间，读全部历史笔记 |
| `--date` | 今天 | `YYYY-MM-DD`，用来指定「现在是哪一周」 |

### 引用门槛

只让引用量够高的论文进候选池，门槛随论文年龄放宽：

| 论文年龄 | 需要引用数（基数为 50 时） |
| --- | --- |
| 发表满 5 年 | ≥ 50 |
| 2–4 年 | ≥ 20 |
| 近两年 | ≥ 5 |

基数存在 `config.json` 的 `citation_base` 里，临时改就在命令行上给 `--min-citations`。

### 年份窗口

先只看近 5 年。近 5 年凑不够 `--per-week` 篇时，自动放宽到近 10 年（可用 `--max-years` 改）。
放宽了几篇、放了多老，都写在周报里，不会偷偷混进来。

### 去重

状态目录的 `进度.csv` 是账本。凡是推过的论文，后面几周不会再出现，即使换了检索式。
这个文件只用来去重，不需要你手工维护。

## 5. 输出在哪、怎么看

### 阅读清单：`<vault>\<周文件夹>\阅读清单.md`

这一周要读的东西，按角色分两组：

- **精读（5 篇）**——每篇有：一句话元信息、链接、主题标签、**为什么读这篇**、**读完你会**得到什么
- **泛读（7 篇）**——同样的结构，但期望更低

清单末尾还有三小节：长期目标里**还没被碰过的那一条**、这一周的**收敛判断**（为什么这样选不算散）、**还悬着的问题**。

### 周报：`<vault>\周报月报\<起始日>_第N周.md`

分 7 节：

1. 上周执行情况——哪些读了、哪些没有笔记提到
2. 你自己写的东西——本周读到的笔记清单
3. 本周清单——选了哪些、写到哪个文件
4. 为什么这样选不算散
5. 长期目标覆盖情况
6. 还悬着的问题
7. **本周工程建议**——任务、需要什么、完成标准、预估工时

第 7 节就是「工程部分」的全部：**建议**，不是代码。

### 总结：`<vault>\周报月报\...总结.md` 或 `<vault>\周报月报\2026-09.md`

`summary` 生成。先是一段脚本算出来的数字（权威，不会被 AI 写错），然后是 AI 的叙述：
一句话、实际做了什么、现在能讲清什么、没做到的、有没有跑偏、下一个周期的唯一重点。
最后留了一节 `代码 / 复现产物` 给你自己填——脚本不碰 git，也不会替你写。

> 周报、周总结、月报都在**同一个文件夹**——库里的 `周报月报\`——所以你在 Obsidian
> 里点开一次就能按时间往下翻；`阅读清单.md` 末尾那句「本周工程建议见 …」是个真链接，点得开。

### Zotero

论文会推进你的 Zotero，统一的标签是 `第N周`。在 Zotero 标签面板点这个标签，就是这一周要读的。

- 走 Zotero 的 **connector** 写入（`http://localhost:23119/connector`），所以**Zotero 必须开着**，只推不读的本地 API 默认是关闭的
- 会尝试给每篇附上 PDF；拿不到 PDF 的仍然推条目，只是没有附件
- 推之前在 Zotero 里已经有同一条目的，不会重复推
- **推不动不会毁掉这一周**：本地该写的文件在推送之前就写完了。连接器只等 30 秒、不重试
  （`saveItems` 是写操作，重试可能塞进重复条目），所以最坏情况下多花半分钟，然后周报里出现一行警告

## 6. 数据写在哪

```text
<vault>\                                    <- 你的 Obsidian 库
├── 长期目标\长期目标.md                     <- 你自己写，脚本只读
├── 2026-09-21_09-27\                       <- 第 1 周
│   ├── 阅读清单.md                         <- 脚本写
│   └── 你的笔记.md                         <- 你写，脚本读
├── 周报月报\                               <- 脚本写；Obsidian 里直接点开
│   ├── 2026-09-21_第1周.md
│   ├── 2026-09-21_第1周总结.md
│   └── 2026-09.md
├── 本周.md                                 <- 选填，一两句话：你现在卡在哪
└── <state_dir>\                            <- 默认 <仓库>\paperflow_state
    ├── config.json                         <- init 生成
    └── 进度.csv                            <- 账本，只用来去重
```

周文件夹名以完整日期开头（`2026-09-21_09-27`），所以按文件名排序永远等于按时间排序，跨年也不会乱。

脚本**只往这些位置写**：`阅读清单.md`、`周报月报\`、`本周.md`、`进度.csv`、`config.json`。
你的笔记和长期目标它一个字都不改。

> **报告写在库里，不在状态目录。** 周报月报是你读的东西，藏进状态目录 Obsidian 就看不见了，
> `阅读清单.md` 里的链接也点不开。所以状态目录里只剩下机器用的两样：
> `config.json` 和 `进度.csv`——换 `--state-dir` 不会把报告和 `本周.md` 一起搬走。
>
> **状态目录不进仓库。** 它在 `.gitignore` 里：`config.json` 记着你的本地路径，`进度.csv`
> 记着哪几篇已经推过，这些都是给你一个人看的。想看文件长什么样，
> 看仓库里的 `paperflow_state.example\`；跑一次 `init` 就会生成真的那份。

## 7. 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `LLM_API_KEY` | `week` 必填 | 任何 OpenAI 兼容的 chat-completions key |
| `LLM_BASE_URL` | 否 | 默认 `https://api.openai.com/v1` |
| `LLM_MODEL` | 否 | 默认 `gpt-4o-mini` |
| `PAPERFLOW_VAULT` | 否 | 填了 `init` 就不用带 `--vault` |
| `PAPERFLOW_STATE_DIR` | 否 | 默认 `<仓库>\paperflow_state`。只放 `config.json` 和账本 `进度.csv`，报告不在里面 |
| `PAPERFLOW_LANG` | 否 | `zh`（默认）/ `en` |
| `S2_API_KEY` | 否 | Semantic Scholar 匿名可用，量大再配；不配会自动回落到 OpenAlex |
| `CONTACT_EMAIL` | 否 | 填了进 OpenAlex / NCBI 的 polite pool，限流更宽松 |
| `NCBI_API_KEY` | 否 | 只影响 PubMed 限流（3 req/s → 10 req/s） |
| `ZOTERO_LOCAL` | 否 | 走本地 connector 时才需要 |
| `ZOTERO_USER_ID` / `ZOTERO_API_KEY` | 否 | 只有在不用 connector、改用 Zotero Web API 时才填 |

### 退出码

| 码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 模型不可用或调用失败、或者 state 目录里没有 `config.json`（本地数据没有被修改） |
| `2` | 参数写错了（包括日期格式），或者 `init` 没给 vault |
| `130` | 你按了 Ctrl-C |

## 9. 常见问题

**控制台中文乱码。**
脚本会自己把标准输出切成 UTF-8。如果你在外部终端里跑还是乱码，先执行：

```powershell
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
```

**`week` 报错说没有模型。**
`LLM_API_KEY` 没读到。检查 `.env` 是否在仓库根目录、key 是否有空格。

**Zotero 没收到论文。**
先确认 Zotero 开着（connector 是它提供的）。周报第 3 节会写明推送结果；`--no-zotero` 跑的那次当然不会推。

**同一周又跑了一次。**
按 `start_date` 算出来还是第 1 周，所以会**覆盖** `阅读清单.md` 和周报，同时往 `进度.csv` 追加。
想先看结果不落盘，就用 `week --dry-run --no-zotero`。

**笔记会被脚本改吗？**
不会。脚本只读笔记和长期目标，只写第 6 节列出的那几个位置。
